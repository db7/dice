Application changes use unrounded CSV values. Raytracing differences are small
relative to run variation. Scratchapixel is dominated by process startup.
These are workload results, not isolated dispatch latency or a scalability test.
CPU frequency, affinity, and thermal state were not controlled.

Microbenchmarks use one thread, a warmup for each version, and seven alternating
pairs of three-second runs. Original loop and handler bodies are preserved.
micro2 exercises a known callback slot in the generated dispatcher; micro3-5
exercise strong linked overrides. Delivery counts match publication counts.

Applications use identical cached instrumented executables and libtsano, with
five alternating pairs after warmup. LevelDB reads five million times from a
populated private database. Scratchapixel averages batches of 50 launches.
Raytracing and Scratchapixel output hashes match across every compared run.

Compared with the earlier 2026-10-05 generator without weak callback fallbacks,
generated micro3/4/5 throughput is approximately 11.6%/4.2%/6.7% lower. The new
version remains faster than the original in these workloads; the flexibility
of weak overrides has an observable cost in this build.

Validation: cmake --build build-roll -j4 and
ctest --test-dir build-roll --output-on-failure -j4: all 51 tests passed.
Coverage includes legacy CMake/object targets, callback/dispatch interleaving,
preload modules, strong overrides with LTO, exact/wildcard callbacks, stop
propagation, invalid slots, checked routes, and embedded callback bootstrap.
